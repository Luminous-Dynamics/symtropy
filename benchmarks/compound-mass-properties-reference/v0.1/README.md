## Source finding

The current RigidBody constructor accepts a vector of inertia values without documenting whether they are principal moments, which frame they use, or what realizability conditions they satisfy. The built-in dynamic_sphere constructor fills this vector with 0.4*m*r^2 in every supported dimension. That is the solid 3D sphere formula, not a general N-dimensional ball formula.

The current merge_toolhead implementation combines the base and toolhead into a compound collider, computes only a scalar mean inertia for the base, assumes the toolhead is a 0.1 m solid sphere, applies a scalar distance-squared parallel-axis adjustment, then writes one identical inertia scalar into every coordinate.

It therefore cannot preserve anisotropic component inertia or products of inertia generated by arbitrary component placement/orientation. The scalar adjustment is not the full tensor parallel-axis theorem.

## Paradigm shift: store mass distribution, derive rotational response

Use the symmetric mass second-moment tensor about the center of mass:

\[
C = \int r r^T\,dm.
\]

For component k with mass m_k, center r_k, local second-moment tensor C_k and local-to-assembly rotation R_k:

\[
M=\sum_k m_k,\qquad c=\frac{\sum_k m_k r_k}{M},
\]

\[
C_{total}=\sum_k\left(R_k C_k R_k^T+
m_k(r_k-c)(r_k-c)^T\right).
\]

This is the tensor parallel-axis theorem. It retains anisotropy and off-diagonal products of inertia. The resulting N-D inertia operator over bivector angular velocity Omega is:

\[
\mathcal I_C(\Omega)=C\Omega+\Omega C.
\]

For a diagonal C, this reduces to independent plane inertias. For a non-diagonal C, different rotation planes couple, and the operator is a dense matrix over D(D-1)/2 bivector coordinates.

The M1 reference implements this dense operator rather than forcing an arbitrary tensor back into D independent scalars.

## Implemented API

- ComponentMassProperties::new validates component mass, centroid, local-to-assembly rotation and local full second-moment tensor.
- CompoundMassProperties::compose computes total mass, COM and full second-moment tensor.
- bivector_inertia_operator constructs the dense plane-space operator by applying C Omega + Omega C to each basis bivector.
- apply_inverse_inertia solves the dense operator for a generalized angular impulse.
- kinetic_energy computes 0.5 * omega^T I_C omega.
- midpoint_mechanical_work checks discrete work at the generalized angular port.

The reference uses explicit Vec-backed matrices and is intentionally not optimized for a production hot loop.

## Known-answer example

Two unit-mass, unit-radius solid spheres each have local C = 0.2 I kg m^2. Place their centers at (0,0,0) and (2,0,0) m. The compound has total mass 2 kg, center of mass at (1,0,0) m, second-moment tensor diag(2.4,0.4,0.4) kg m^2, and plane inertia spectrum (J_01,J_02,J_12) = (2.8,2.8,0.8) kg m^2.

The fixture also tests a rotated anisotropic component, which produces nonzero off-diagonal products of inertia.

## Validation corpus

Tests cover single-component preservation, two-offset-sphere parallel-axis known answer, rotated anisotropic products of inertia, component-order invariance, dense operator versus direct tensor action, midpoint work versus exact kinetic-energy change, and invalid mass/tensor/rotation inputs.

The JSON fixture file preserves the known-answer examples and claim ceiling.

## Promotion path

- **M0:** map every constructor, deserialization and mutation path for the current inertia vector.
- **M1:** verify the full tensor composition and dense bivector operator (this reference).
- **M2:** define a versioned production MassProperties contract and migration path; replace merge_toolhead scalarization.
- **M3:** derive shape mass properties for spheres, boxes, rods and compounds in 3D, then add supported N-D shapes.
- **M4:** validate free rotation, torques, collision impulses and energy conservation against independent rigid-body references.
- **M5:** migrate hinge effective mass, motor response and contact response onto the same qualified operator.

## Claim ceiling

This code validates a mathematical reference with synthetic inputs. It does not prove that current production RigidBody inputs are principal moments, does not change merge_toolhead, and does not qualify a physical mechanism, robot, exoskeleton or human-contact system.
