# HumanStudy-Bench native output contract (pinned paths)

This is a source-derived path map for the two protocols used by the CIVDYN receipt gate. All paths are relative to the native run or config directory. Hash exact bytes before parsing.

## Paper repository: `AISmithLab/HumanStudy-Bench`

The pinned `docs/RESULT_STORAGE.md` documents:

```text
results/runs/<run_name>/<study_id>/<model>_<prompt>/
  full_benchmark.json
  detailed_stats.csv
  evaluation_results.json
  [raw_responses.json]
```

Required receipt roles:

| Role | Path | Authority |
|---|---|---|
| `paper_full_benchmark` | `full_benchmark.json` | Original simulation/run payload and usage |
| `paper_detailed_stats` | `detailed_stats.csv` | Original detailed statistical table |
| `paper_evaluation_results` | `evaluation_results.json` | Official PAS/ECS and per-test evaluator outputs |

Optional: `paper_raw_responses` at `raw_responses.json` where present. Aggregate summary tables in `results/benchmark/` are derived outputs; record them as separately identified baseline artifacts, never as substitutes for the native run files.

## CIVDYN paper-run attestation sidecar

The paper importer requires `civdyn_paper_run_attestation.json` in each native per-study config directory. This is not generated by upstream. It binds the native result files to the exact paper source revision, study config/evaluator, global runner/evaluator/metric sources, prompt, model label, run ID and declared independent unit:

```json
{
  "protocol_id": "HSB-PAPER-12-CF05D330",
  "source_repository": "AISmithLab/HumanStudy-Bench",
  "source_commit": "cf05d330fc315168c8c8e23b4acd882f91bb7408",
  "study_id": "study_001",
  "study_config_blob_sha": "63fe04388eccca7088ba8e76834014511797e2bd",
  "evaluator_blob_sha": "612428dac96758f7d3e68fe8882133af13be5242",
  "baseline_runner_blob_sha": "4572ad360135d591e6a9d3d1f2c91a4bba3d099c",
  "generation_runner_blob_sha": "5604a469aea0e1b5f5b9ebd94f55587f1d50cf18",
  "generation_pipeline_blob_sha": "76ef97ae5939c493f6de66925ae76756b3a5b9d3",
  "evaluator_runner_blob_sha": "0b67c4c31d491932655258e84a2ca1609ad74b46",
  "stats_lib_blob_sha": "24bc535b0d21cef24dd5b7139209478134c57d64",
  "analysis_protocol_preserved": true,
  "run_id": "synthetic-paper-run-001",
  "model_id": "synthetic-model-not-a-real-run",
  "prompt_preset": "v3_human_plus_demo",
  "prompt_template_sha256": "dddddddddddddddddddddddddddddddddddddddddddddddddddddddddddddddd",
  "independent_unit": "participant"
}
```

The study config and evaluator blob values must match the study-specific source pins. The five global source fields must match the `execution_sources` table in `foundational_12_profile.json`:
- `baseline_runner_blob_sha`: `scripts/run_baseline_pipeline.py`
- `generation_runner_blob_sha`: `generation_pipeline/run.py`
- `generation_pipeline_blob_sha`: `generation_pipeline/pipeline.py`
- `evaluator_runner_blob_sha`: `src/evaluation/evaluator_runner.py`
- `stats_lib_blob_sha`: `src/evaluation/stats_lib.py`

The prompt SHA-256 is computed by the run wrapper from the exact prompt template bytes and is carried as an operator attestation. The independent sampling unit must be declared from the original study design; it is not inferred from the number of response rows.

`analysis_protocol_preserved=true` is also operator-attested. The importer requires it and validates all declared source blob identities, but cannot independently prove that the external process actually ran those source files, that provider weights were unchanged, or that the declared prompt bytes were used. Preserve original environment/run logs and use an immutable environment/container digest for any claim of a complete reproduction.

The sidecar schema is `paper_run_attestation.schema.json`; a synthetic conformance-only example is in `fixtures/synthetic_paper_run_attestation.json`. The importer records the sidecar as `paper_run_attestation`. This does not independently prove process execution or model-weight identity; preserve upstream environment/run logs as additional evidence when making a reproduction claim.

## Community repository: `HumanStudy-Hub/HumanStudy-Bench`

The pinned Community Edition `playground/README.md` and `playground/run_playground.py` document:

```text
<run-dir>/
  run.json
  progress.json
  output/
    profiles.json
    responses.json
    evaluation.json
    analysis.json
    transcript_sample.json
    charts.json
    charts.default.json
```

Required receipt roles:

| Role | Path | Authority |
|---|---|---|
| `community_run_manifest` | `run.json` | Run settings/model/prompt provenance |
| `community_responses` | `output/responses.json` | Participant-response payload passed to evaluator |
| `community_evaluation` | `output/evaluation.json` | Study-native evaluator output |
| `community_analysis` | `output/analysis.json` | Normalized one-row-per-test analysis |

Optional: `community_profiles`, `community_transcript_sample`, `community_charts_non_authoritative`. Charts are presentation artifacts. `output/analysis.json` does not automatically contain the original paper's benchmark-level PAS/ECS.

## Importer invariants

- Hash each file as raw bytes before UTF-8/JSON/CSV parsing.
- Store path, role, byte count, record count if known, SHA-256, rights basis and privacy classification.
- Do not normalize unknown fields away. Keep the original artifact as the source of truth.
- If an expected native artifact is missing, fail the exact-reproduction receipt. Do not synthesize a substitute from a summary.
- Do not infer the independent statistical unit from row count; map it from the study's original design and evaluator.
- Keep charts, LLM-generated summaries and aggregate dashboards explicitly non-authoritative.
