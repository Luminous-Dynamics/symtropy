# Open-world domain falsification benchmark v0.1

**Status:** synthetic reference implementation and research benchmark.  
**Parent:** [ORBITAL-OPEN-WORLD-DOMAIN-001 #7001](https://github.com/Luminous-Dynamics/symtropy/issues/7001).  
**Stacked on:** [action-universe closure #6996](https://github.com/Luminous-Dynamics/symtropy/pull/6996) / [#6959](https://github.com/Luminous-Dynamics/symtropy/issues/6959).  
**Claim ceiling:** independent finite-domain grammar falsification only.

## Why an independent domain generator is needed

A list hash establishes the identity of a supplied action list. Two enumerators agreeing establishes agreement between those enumerators. Neither establishes that the decision problem includes every action that should be considered.

Even separate implementations can share one missing capability primitive, ontology row, upstream catalogue, requirement decomposition or source API. The benchmark therefore constructs a bounded action universe from a separate finite grammar and tests both candidate enumerators against that generated universe.

This is deliberately narrower than a claim about the physical world. The grammar is a synthetic ground truth for finite falsification. An external challenge can still show that the grammar itself is inadequate.

## v0.1 grammar

The finite grammar contains:

- Components with capability sets, resource capacity and active time intervals.
- Operations with a required capability, required actor role, resource demand and active interval.
- Actors with role sets and active intervals.
- A domain-wide time window and immutable/current snapshot digests.

The reference generator performs a Cartesian traversal over components × operations × actors and admits an action only when all predicates hold:

`capability(component, operation)
∧ resource_capacity(component) ≥ demand(operation)
∧ role(actor, operation)
∧ overlap(domain, component, operation, actor)`.

The action identity is a canonical tuple of component, operation and actor IDs. The payload digest binds that tuple under the v0.1 action-domain encoding.

The registry and model enumerators do not provide the oracle's expected set. Their lists are compared only after the grammar generator independently derives the finite action set.

## Status semantics

| Status | Meaning |
|---|---|
| `CLOSED_WITHIN_GENERATED_DOMAIN` | Both enumerators exactly match the generated finite grammar and the snapshot is current. |
| `COMMON_MODE_ACTION_OMISSION` | Both enumerators omit at least one action generated by the independent grammar. Agreement between them does not hide the omission. |
| `ENUMERATOR_DISAGREEMENT` | At least one enumerator is incomplete and the missing actions are not jointly omitted, or their sets otherwise differ. |
| `DOMAIN_MODEL_INADEQUATE` | An independently witnessed in-scope challenge action is absent from the generated grammar. |
| `DOMAIN_SNAPSHOT_DRIFT` | The domain snapshot changed after the grammar evidence was bound. |
| `STALE_ENUMERATION` | One or more enumerator receipts reference another snapshot. |
| `ENUMERATOR_OUTSIDE_DOMAIN` | A source enumerator reports an action that the generated finite grammar does not admit. |

## Frozen controls

Seven cases are included:

1. Positive bounded domain with two enumerators matching the generated universe.
2. Both enumerators omit the same generated calibration action.
3. One enumerator omits an action and the other does not.
4. A separately witnessed in-scope calibration action is missing from the grammar, forcing `DOMAIN_MODEL_INADEQUATE`.
5. Domain snapshot drift.
6. One stale enumerator snapshot.
7. A source enumerator inserts an action outside the generated grammar.

The grammar also contains negative combinations that must not be generated: a weak component lacks the required resource capacity; an observer lacks the technician role; and a repair operation exceeds the component's declared capabilities/resources.

## Limits and next falsification step

The independent generator still consumes a finite manifest. The receipt does **not** prove that the manifest's components, operations, actors, capabilities, roles, resource limits or time windows represent a real operational domain. External challenge witnesses are supplied as opaque IDs plus payload commitments; v0.1 does not authenticate their issuer or evidence content.

The next version should use independently authored generator families, mutation-based domain expansion, and counterexample generation from a separate held-out domain grammar. It should test whether new capabilities, actor roles, configurations, time regimes, prerequisites and resource transitions create valid actions unknown to every enumerator. Any newly found action invalidates the affected closure receipt and all downstream global-regret/policy claims tied to that scope snapshot.

This is related to open-world model adequacy research: a model class must retain a way to say “none of the current hypotheses is adequate,” rather than normalizing every counterexample into the existing grammar. Reuse [SIM-REL-004 #2921](https://github.com/Luminous-Dynamics/symtropy/issues/2921) for that general model-class inadequacy concept; this benchmark owns only its decision-action-domain instantiation.

```sh
cargo test --locked --manifest-path tools/orbital-observation-surface-bench/Cargo.toml --all-targets
cargo clippy --locked --manifest-path tools/orbital-observation-surface-bench/Cargo.toml --all-targets -- -D warnings

  tools/orbital-observation-surface-bench/fixtures/v0.1/open-world-domain-cases.json \
  --source-commit <40-character-commit-sha>
```

The dedicated workflow also runs the independent Node oracle, validates corpus/receipt schemas, compares outputs and uploads source-pinned artifacts.

## Acceptance targets

These are prospective targets, not results:

- 100% exact Rust/independent-oracle agreement on the frozen finite cases.
- Zero common-mode omissions accepted as closed.
- Zero externally witnessed challenge actions silently folded into a supposedly complete grammar.
- Zero stale closure evidence after a snapshot mutation.
- Zero unauthorized or resource-infeasible actions generated.
- 100% deterministic output under permutation of components, operations, actors and enumerator rows.
- Report generator runtime and complexity separately from source-enumerator runtime and solver runtime.

A 100% agreement rate on this finite grammar is only software conformance. Real-domain adequacy requires independent domain modelling, external adjudication and field evidence.
