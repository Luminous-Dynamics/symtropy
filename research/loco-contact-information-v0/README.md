# LOCO Contact Information V0

Standalone dependency-free Rust reference oracle for [LOCO-CONTACT-INFO-001 / #4004](https://github.com/Luminous-Dynamics/symtropy/issues/4004).

## Scope

V0 uses a fixed three-dimensional latent Gaussian state per foot/contact event. The three entries are generic, declared latent contact quantities; callers must define physical units and semantics for each benchmark fixture. It is **not** a validated estimator of physical friction coefficient, CoP, support force or terrain compliance.

For prior state:

    x ~ Normal(mu, P)

and a scalar measurement:

    y = h x + epsilon,  epsilon ~ Normal(0, r)

the exact update is:

    S = h P h^T + r
    mu_post = mu + P h^T (y - h mu) / S
    P_post = P - (P h^T h P) / S

The expected information gain for a measurement is:

    EIG = 0.5 * ln(1 + h P h^T / r)

Multiple scalar measurements are processed in canonical order. V0 requires the caller to explicitly qualify conditional noise independence. Correlated channels, repeated observations from one sensor/event and duplicated evidence IDs are rejected rather than double-counted.

## Implemented

- Fixed 3D symmetric-positive-definite Gaussian prior and posterior.
- Exact scalar linear-Gaussian measurement update.
- Expected information gain in nats.
- D1 interface, D2 near-foot wrench, D2 vibro-acoustic and D3 proprioceptive channel identities.
- Contact-event, foot, sensor, sample, clock and measurement-model identity receipts.
- Acquisition/arrival time ordering, verified timebase and bounded sample age checks.
- Duplicate evidence and repeated model rejection.
- Measurement models bound to the commanded action and actuator-model digest.
- Observation receipts bound to an action-execution receipt containing command ID, delivered-action ID, measured-actuation digest and matching actuator-model digest.
- Clock-mapping receipt IDs required alongside source-clock identity and the timebase-verification flag.
- A shared source-qualified noise-independence certificate ID across the selected model set; per-channel Boolean independence assertions are not accepted as pairwise evidence.
- Action-conditioned updates reject replayed observations, action/model mismatch, actuator-model mismatch, missing clock-mapping receipts and unverified delivery receipts.
- Physical hard-envelope filtering for energy, support margin, normal force, impact impulse and actuator load.
- Pareto frontier over information, energy, support margin, peak force, impact and actuator load. No weighted single-score substitution.
- Deterministic ordering and fail-closed numeric/identity checks.

## Evidence boundaries

The information model assumes the supplied linear observation rows and noise variances are calibrated and valid for the declared action/contact regime. V0 does not estimate them from data. The shared noise-independence certificate is an upstream qualification reference; this package checks that the entire selected model set points to the same certificate but does not independently verify the certificate's source evidence.

Every measurement model names the command action and actuator-model digest for which it was calibrated. Each update requires an action-execution receipt that binds the command ID, delivered-action ID, measured-actuation digest and matching actuator-model digest. Observations carry a clock-mapping receipt ID, but the mapping artifact is not independently verified. The upstream action-delivery and clock-mapping verifiers remain in the trust boundary: `delivery_verified` and `timebase_verified` are not cryptographic proofs generated by this package.

The hard-envelope fields are caller-supplied conservative prediction bounds. This oracle does not compute contact feasibility or certify a robot safe. Its role is to reject candidates whose supplied envelope is outside declared limits. A result marked feasible means only that the supplied envelope lies within the supplied limits.

V0 assumes one foot/contact event per update call, one sample per measurement model per event, and conditionally independent scalar measurement noise under a shared upstream certificate. It does not yet support cross-foot correlated contact states, joint multivariate sensor covariance, clock-offset estimation, nonlinear contact modes or sensor-health learning.
