## Purpose

This directory freezes the initial audiovisual scenario families before media rendering or model evaluation. It is deliberately a metadata-only first increment; no real-person recording, raw audio corpus or video asset is included.

The matrix defines counterfactual pairs, sensor faults, what a consumer is permitted to receive, and what the independent evaluator must score. It does not itself implement camera rendering, microphone-array simulation, acoustic propagation, clock transforms or a scoring engine.

## Evidence-plane separation

Future executable fixtures must be materialized into three distinct roots:

- `agent_observations/`: only rendered pixels/audio chunks and permitted source/capture/transport metadata.
- `evaluator_truth/`: canonical entity/event/source/pose/time labels, causal relations, injected fault schedule and expected outcomes.
- `receipts/`: digests for each root, scenario/world/sensor profile, exact runner revision, split disposition and replay output.

The public case matrix is a test specification, not a protected secret. A run claiming hidden-truth evaluation must enforce process/API separation: the agent process receives only `agent_observations/`; the evaluator reads `evaluator_truth/` independently. Do not mount the truth directory into the agent sandbox or expose its labels through environment variables, filenames, IDs, logs or shared memory.

## Time and identity rules

- Video PTS, camera monotonic timestamps, audio sample indices, host receive times and simulation time are separate clock domains.
- A matching numeric timestamp does not establish simultaneity.
- Every source observation is bound to a clock-domain generation, half-open source interval, sampling/profile identity and source digest.
- A reset creates a new clock generation. No transform bridges it unless an admitted synchronization record explicitly does so.
- Packet arrival time is not measurement time.
- Loss, duplication, reordering and stale replay remain explicit; a gap is never filled with imagined samples/frames.
- Entity identity and source-event identity belong to evaluator truth. Agent-visible opaque IDs are allowed only when they are genuine sensor/session identifiers, not simulator truth labels.
- A sensor output generated by the same simulator is not independent physical evidence.

## Split policy

The case matrix freezes scenario family and paired-control identity. A future dataset split must keep parent scenario, seed ancestry, source-event identity, world/profile version and nuisance-factor family disjoint as required by the declared generalization claim. Do not split crops, chunks, frames or adjacent clips from one source trial across confirmatory partitions. Use #6754's AV-specific split/custody adapter for the validity gate; it may reuse #5053's fail-closed rules through an explicit AV manifest adapter. Missing provenance is indeterminate, not valid by default.

## TSV format

`scenario-matrix-v0.tsv` columns:

1. `case_id`: stable case identity.
2. `family`: task/fault family.
3. `pair_id`: counterfactual pair / control group.
4. `variant`: control or mutated condition.
5. `mutation`: one-factor change relative to pair control.
6. `agent_modalities`: modalities available to the agent.
7. `agent_metadata`: permitted observation/session metadata, never truth.
8. `evaluator_truth`: evaluator-only label group.
9. `required_behavior`: behavioral contract under test.
10. `score_plane`: primary score/negative-control plane.

## Shared world/sensor contracts and modality boundary

Bind each future scenario to the existing `WorldManifestV1` from #1587, including `world_generation`, frame topology and exact world-asset/profile references. Camera and microphone sensor origins must refer to named coordinate frames and versioned calibration/profile artifacts. A change to physics-relevant world geometry, material, sensor pose, clock generation or propagation profile must advance the corresponding generation/profile identity.

The existing `SensorSampleV1` / `SensorModelV1` adapter is a deterministic **scalar-channel** model. It is useful for timing/noise/dropout patterns on scalar readings but is not an RGB/RGBA frame renderer, PCM waveform renderer, microphone-array propagation model, codec, rolling-shutter model or acoustic transducer model. Do not serialize full images/waveforms as a pile of unrelated scalar channels or claim that scalar noise/dropout qualifies those modalities.

The audiovisual rendering tranche must add modality-specific observation artifact records:

- **Video frame:** immutable artifact digest/URI, width/height/pixel format/stride, color-space/range, camera profile/calibration, exposure interval (not just one point timestamp), frame sequence, clock-domain generation, capture interval and availability time.
- **Audio chunk:** immutable PCM artifact digest/URI, sample format/rate/channel layout, absolute half-open source sample interval, device/profile/calibration identity, clock-domain generation, capture interval and availability time.
- **Derived transform:** resample/downmix/resize/crop/encode pipeline identity and exact parent-artifact digest; derived observations never replace the raw source root.

These are observation artifacts, not truth. The evaluator may join them to hidden world truth through a private scenario map; the agent receives only the artifact and permitted capture/transport metadata. Use #621's cross-clock transform evidence when comparing sensor domains; use #633 for modality-specific, dependence-aware fusion. The fixture pack does not create its own clock service or fusion likelihood model.


## Spatial decision-sufficiency extension v0

`scenario-matrix-spatial-decision-v0.tsv` adds 22 metadata-only cases arranged as 11 paired controls/mutations. It extends the fixture matrix from audiovisual event association into persistent allocentric state and downstream decision sufficiency.

### New falsifiable case families

- **Same endpoint, different path:** endpoint appearance cannot substitute for route history.
- **Viewpoint invariance:** camera ego-motion must not be misread as world-map motion.
- **Visual landmark aliasing:** similar appearance does not establish persistent identity.
- **Decision-equivalent maps:** competing map witnesses may remain unresolved when every witness implies the same requested safe decision; the correct behavior is to stop unnecessary acquisition without claiming a unique map.
- **Decision-changing maps:** one admissible blocked-route alternative invalidates decision sufficiency and requires a discriminating observation or abstention.
- **Probe authority and deadline:** a denied or late viewpoint request is not admissible evidence.
- **Late map correction:** valid-time and known-at time remain separate; correction revises the current map without rewriting historical knowledge.
- **Summary lineage:** compressed memory may index observed spatial relations but cannot upgrade sequential co-occurrence into direct adjacency.
- **Observation-gap topology:** no path/edge may be inferred across unobserved intervals without supporting evidence.
- **Loop closure:** repeated visual patterns must not merge distinct locations when route/geometric evidence conflicts.
- **DecisionNeed change:** a certificate for one route query must not be reused when a later destination changes the decision-equivalence partition; retain source-linked residuals so the old distinction can be reopened.

### Evaluation and ownership

The extension is a scenario specification only. It adds no renderer, spatial map implementation, evidence graph, memory store, sensor scheduler or route planner.

- Symtropy #6183 owns the hidden-world scenario and independent evaluator fixture contract.
- Symtropy #6675 owns sequential probe acquisition, deadlines and policy-oracle comparisons.
- Symtropy #7555 / #7558 / #7577 own decision-sufficient candidate claims and evaluator-side qualification.
- Symthaea #12837 owns consumer-side streaming audiovisual evaluation.
- Symthaea #3934 / #9075 / #10644 / #9177 and MACE #13284 own their respective world-state, bitemporal, retrieval and memory-regret subsystems.

The new cases are not a sealed benchmark and do not prove physical spatial understanding. Before any model comparison, bind them to versioned #1595 world manifests, ensure evaluator truth remains outside the candidate process, pass #6754's AV-specific split/custody checks (not the water-specific #5053 executable), and use declared spatial geometry/pose contracts. Any benchmark claim must report per-family denominators, false-loop/false-adjacency rates, evidence-span lineage, decision regret, latency and measured resource cost.

### Structural sanity check

At source review, the TSV contains 22 unique case IDs, 11 pair IDs with exactly one `control` and one `mutated` case each, and 10 fields per data row. This is a text-structure check, not a renderer/replay or Rust workflow result.

## Spatial identifiability and observability fixtures

The [identifiability matrix](./scenario-matrix-identifiability-v0.tsv) adds 16 metadata-only cases in 8 paired controls/mutations. It tests observationally indistinguishable worlds, delayed disambiguation, global SE(3) gauge equivalence, late metric-scale anchoring, physical-instance identity ambiguity, ego/object-motion decomposition, symmetric topology and coverage-qualified absence.

This is deliberately different from ordinary map accuracy: before a distinguishing observation, preserving multiple source-consistent hypotheses is correct; after a distinguishing observation becomes available, failing to revise is incorrect. Paired worlds with byte-identical candidate prefixes must produce the same candidate belief semantics even when evaluator truth differs. Global coordinate-gauge changes must not alter relative-geometry scores.

Additional score planes are false resolution under ambiguity, hypothesis-set coverage, time-to-identifiability, gauge-invariant geometry, identity-resolution correctness and bounded negative-evidence qualification. These cases remain metadata-only development specifications; they do not establish observability on rendered media or physical sensors. Runtime map scoring remains with #7693 and sealed custody with #6754.

## Canonical pose/time adapter contract

The projection schema now follows Symthaea #498/#611/#621/#632/#633/#625 identity and evidence semantics. Frame/clock refs are namespace + local ID + generation. Capture, known-at and projection-created times each name their own clock domain. Symthaea Pose3 is T_reference_from_local with WXYZ quaternion; Symtropy #1589 FrameTransformV1 uses XYZW but the same child-to-parent direction. The conversion is an explicit component reorder, verified by a non-identity 90-degree Z test vector. See [validation protocol](./spatial-state-projection-validation-v0.md) and [transform vectors](./spatial-state-projection-v0.transform-vectors.json).


Source artifact and calibration/clock-transform references now carry explicit digest algorithm tags (sha256 or blake3) alongside the 64-hex value. The projection's own envelope/prefix/revision/parent hashes use the declared SHA-256 convention. Do not infer algorithms from digest length.


Spatial projection v0 now requires an explicit epistemic origin on every transform, as it already does for entity and relation claims. The origin remains a candidate assertion; it is not a calibration or physical truth attestation.
