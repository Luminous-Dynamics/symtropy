# SIM-REL-002 bounded grammar harness (v0)

This isolated, dependency-free Rust crate advances [SIM-REL-002](https://github.com/Luminous-Dynamics/symtropy/issues/2886) from a protocol into an executable prototype. It generates candidate Boolean functions from a declared grammar instead of accepting a supplied list of candidate models.

## Model class

Three binary inputs `x,y,z`; eight intervention assignments (action IDs 0 through 7); constants `0,1`; unary `NOT`; binary `AND`, `OR`, and `XOR`; syntax-tree depth at most two. Commutative child expressions are text-ordered; unique truth-table signatures are grouped into semantic classes. Each class retains a shortest representative expression and a count of the syntactic expressions generated by this enumerator.

The depth cap is a model-class restriction, not a claim about Boolean functions in general. For the declared v1 grammar, tests expect 5 semantic functions at depth zero, 17 at depth one, and 109 at depth two. The majority function `00010111` is an explicit out-of-grammar control for depth two.

## Information boundary

- `fixtures/problems-v0.tsv` is the agent-facing task list: task ID, split, initial observations, and query budget.
- `fixtures/evaluator-truth-v0.tsv` is a separate evaluator-only file containing target signatures. The action-selection policy receives only surviving hypotheses and available actions; evaluator truth is used by the runner solely to synthesize feedback and score outcomes.
- For any real agent-facing deployment, keep the truth fixture outside the agent's filesystem/process boundary. Separate filenames are not a security boundary by themselves.

## Policies and conservative outcomes

Three policies share the same grammar and budget: greedy maximum-disagreement, fixed ascending action, and seeded-random action (32 repetitions per task). When a single candidate remains and budget permits, the runner makes one post-fit falsification probe: the active policy chooses an unqueried input where the broader grammar's candidates most disagree with the provisional candidate; fixed/random policies use their respective selection policies. If that observation contradicts the singleton, the task is labelled `misspecified`. A successful single audit is not proof of the full rule: unless all eight inputs have been observed, the outcome remains `provisional_unique`. The status `identified_exactly` requires one remaining semantic candidate and observations at all eight inputs. Ambiguous cases remain ambiguous.

Receipts include the exact Git HEAD, hashes of both input fixtures, the grammar candidate catalog, query counts, remaining semantic classes, and outcomes by policy/split. The runner rejects an incorrect expected HEAD and a dirty checkout before it reads the fixtures. Write outputs outside the checkout so the receipt itself does not dirty the repository.

## Run

From the repository root, use an actual reviewed commit SHA for `EXPECTED_HEAD`:

```bash
cargo fmt --manifest-path tools/sim-rel-grammar/Cargo.toml -- --check
cargo test --locked --manifest-path tools/sim-rel-grammar/Cargo.toml --bin sim-rel-grammar
EXPECTED_HEAD="<reviewed-40-hex-commit>"
cargo run --locked --manifest-path tools/sim-rel-grammar/Cargo.toml --bin sim-rel-grammar -- \
  --problems tools/sim-rel-grammar/fixtures/problems-v0.tsv \
  --truth tools/sim-rel-grammar/fixtures/evaluator-truth-v0.tsv \
  --expected-head "$EXPECTED_HEAD" \
  --max-depth 2 \
  --out /tmp/sim-rel-002-receipt.json
```

Use `--out -` for JSON on stdout. Any edited or untracked non-ignored file in the checkout intentionally causes the clean-checkout gate to fail.

The dedicated [SIM-REL-002 workflow](../../../actions/workflows/sim-rel-grammar.yml) validates the receipt and uploads it as a 30-day artifact named `sim-rel-002-receipt-<exact-head-sha>`. This makes the machine-readable receipt inspectable after the runner finishes; a green workflow check without the matching receipt artifact is not sufficient qualification evidence.

## Scope and qualification

This is a finite, synthetic truth-table experiment. It is **not** a physical-system grammar learner, not a direct comparison to published benchmark scores, not proof of a shared grammar across worlds, and not validation of Chain Theory. Current source has not been compiled/run in the current authoring environment because a Rust toolchain is not installed. The test suite is authored, not passing evidence, until a Rust-enabled exact-head run produces and inspects a receipt.

### Next gates

1. Compile and run on exact HEAD; inspect every test and JSON receipt.
2. Expand to at least 100 independently generated worlds, grouped by rule family rather than random rows; add hidden initial-condition variation and sealed held-out families.
3. Add a post-discovery falsification budget so a unique candidate is actively challenged on an unqueried intervention instead of stopping on fit alone.
4. Add noisy observations and calibrated expected-information-gain selection.
5. Implement typed graph-rewrite / spring-mass grammar induction and compare against strong equation and graph baselines at matched query and compute budgets.
6. Require independent replication before any superiority claim.

## Research context

- [EurekaBench (2026)](https://arxiv.org/abs/2610.00492) evaluates long-horizon scientific discovery through constraints, predictive accuracy, and the scientific insights supported by a discovered mechanism—not prediction alone.
- [NewtonBench (2025 preprint)](https://arxiv.org/abs/2510.07172) studies interactive law discovery across diverse physics tasks.
- [AI Feynman](https://pmc.ncbi.nlm.nih.gov/articles/PMC7159912/) is a symbolic-equation discovery baseline.
- [SRBench 2025](https://doi.org/10.1145/3712255.3734309) emphasizes standardized execution budgets and reports that no single symbolic-regression method dominates all datasets.
- [Olko et al., ICML 2025](https://proceedings.mlr.press/v267/olko25a.html) identifies faithfulness violations as a major limitation in neural causal discovery.
- [Brouillard et al., CLeaR 2025](https://proceedings.mlr.press/v275/brouillard25a.html) calls for more realistic causal-discovery data and better evaluation metrics.

These are methodological references, not scores directly comparable to this small Boolean task.
