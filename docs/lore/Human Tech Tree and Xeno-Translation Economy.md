# Symtropy Design Doc: Human Tech Tree and Xeno-Translation Economy

## Working Title

**Technology Is Infrastructure That Learned to Remember**

## Core Thesis

Technology progression in *Symtropy* must not be a passive menu where players spend points for abstract percentage buffs.

Humanity’s tech tree is a physical infrastructure evolution tree.

Advancing technology means unlocking:

```text
manufacturing methods
material tolerances
thermodynamic stability
script execution budgets
Field Deck bandwidth
Device Bus complexity
cargo throughput
repair legitimacy
charter broadcasting
multi-species translation capacity
```

Core rule:

```text
You do not research technology by spending points.
You earn technology by building the conditions that make it possible.
```

---

# 1. The Three Human Disciplines

Human baseline progression is organized into three primary engineering disciplines.

```text
1. Thermodynamic Material Fabrication
2. Computational Field Architecture
3. Socio-Civic Legitimacy Chains
```

These are not isolated skill trees.

They are interdependent infrastructure layers.

A better pipe may require better metallurgy.

Better metallurgy may require better power control.

Better power control may require better scripts.

Better scripts may require better civic authority.

Better civic authority may require witnessed labor and trusted archives.

Design rule:

```text
A technology is unlocked only when matter, computation, and legitimacy can all support it.
```

# 5. Cross-Cutting Gate: Metabolic Translation & Consent

This is not a normal human tech tree.

It is the gate that allows alien technology to enter human infrastructure.

## Purpose

Alien artifacts cannot be treated as downloadable blueprints.

Alien systems may rely on:

```text
water memory
aerosol bodies
crystalline resonance
slow cognition
bio-electric membranes
living root computation
reef consensus
fungal routing
non-human time scales
```

A human workbench cannot simply craft these.

The player must build translation infrastructure.

Core rule:

```text
Alien technology is not acquired.
It is negotiated into compatibility.
```

# 6. Alien Trade: Metabolic Gradients, Not Currency

Alien civilizations do not value human credits by default.

Trade occurs through direct metabolic exchange.

The player offers maintenance, stability, remediation, or translation labor that improves the alien civilization’s survival conditions.

In return, the alien civilization provides materials, access, testimony, routing, memory, or hybrid capability.

# 8. Xeno-Technology Translation Loop

Alien hardware translation happens in three steps.

## Step 1: Hardware Handshake

The player physically connects the Field Deck to an alien artifact.

Connection methods may include:

```text
copper patch cable
bio-electric clamp
seismic contact plate
aerosol intake membrane
wet-contact bridge
crystal resonance fork
```

Field Deck:

```text
SCAN:
Non-human artifact detected.
Interface geometry incompatible.

DIAG:
Signal substrate unknown.
Translation pool required.
```

Design rule:

```text
First contact begins with a cable that does not quite fit.
```

---

## Step 2: Translation Pool Calibration

The player maps alien logic to human infrastructure parameters.

Examples:

```text
alien “breathing” → human pressure cycling
alien “hunger” → nutrient or current draw
alien “rest” → maintenance dormancy window
alien “song” → acoustic command rhythm
alien “kinship” → source-chain authorization set
alien “pain” → overload / consent violation warning
```

Example failure:

```text
Canopy Root blueprint expects nutrient flow.
Human system provides only 12V DC.
Translation wrapper required.
```

Design rule:

```text
Translation is not language conversion.
It is responsibility mapping.
```

---

## Step 3: Xeno-Hybrid Block Compilation

Once calibrated and witnessed, the system can compile a hybrid component.

Example:

```text
/dev/sym/hardware/hybrid_filter_alpha
STATUS: ACTIVE
METABOLIC_RATE: STABLE
POWER_INPUT: 12V DC
CONVERSION: BIO-ELECTRIC PULSE
XENO_LOGIC: Canopy Root Biofilm
RIGHTS_STATUS: FORUM-LICENSED
RISK: 2.4% Null Drift
```

Design rule:

```text
A hybrid block is not just equipment.
It is a living treaty under load.
```


Technology should not appear as a menu node alone.

It should appear as:

```text

new cartridge
new tool head
new Device Bus command
new public charter clause
new cargo type
new facility room
new witness procedure
new failure mode
new NPC argument
```

Example:

```text
Unlocking Public Works Fabrication does not give +5% repair speed.

It gives:
- certified pipe gauges
- pressure test rig
- better seals
- public tool library
- new inspection requirement
- stronger repair legitimacy
```

Design rule:

```text
Every technology should add a new physical verb or institutional consequence.
```

# 12. Relationship to Proof-of-Repair

Proof-of-Repair should influence technology access.

A settlement may grant advanced tools because the player’s source chain proves prior competence.

Example:

```text
CIVIC:
Proof-of-Repair recognized.
Old Waterworks restoration accepted.

ACCESS UNLOCKED:
Public Works Fabrication Bench
```

But Proof-of-Repair is not a spendable currency.

Design rule:

```text
Your repair history opens doors.
It is not a bag of coins.
```

# 14. Final Principles

```text
Technology is not a menu.
It is an achieved condition.

Human progression has three disciplines:
matter, computation, legitimacy.

Alien progression enters through translation and consent.

Trade is metabolic before it is financial.

A hybrid device is a treaty under pressure.

The best tools require better infrastructure and better trust.

The player does not buy the future.
They build the conditions that make the future safe to operate.
```

Final line:

```text
Humanity did not climb the tech tree.
It repaired the ladder, proved who held it, and learned that some branches were alive.
```
