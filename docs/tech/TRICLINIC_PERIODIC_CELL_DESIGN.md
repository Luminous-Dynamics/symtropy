# Triclinic Periodic Cells and Closest-Lattice-Image Contract

**Status:** geometry-only prototype; exact-head execution required.  
**Tracking:** [PHYS-TOPOLOGY-003 #2989](https://github.com/Luminous-Dynamics/symtropy/issues/2989).  
**Prerequisite:** [orthogonal periodic primitives PR #2884](https://github.com/Luminous-Dynamics/symtropy/pull/2884).

## Why this is a distinct capability

An orthogonal periodic box can wrap each Cartesian axis independently. A skew cell is generated by a lattice basis, and the closest Cartesian image is a closest-vector problem. Rounding each fractional coordinate independently produces a nearby lattice point, but not necessarily the nearest Cartesian image.

GROMACS supports triclinic periodic boxes and documents that minimum-image interactions have geometric restrictions based on the shortest box vectors; it also uses lattice translations to identify periodic images. Symtropy's first version is not a replacement for those production molecular-dynamics algorithms. The immediate goal is a small, independently testable lattice geometry primitive that later collision code can build on.

## Coordinate convention

`TriclinicPeriodicCell<D>` stores lattice vectors as the **columns** of a full-rank matrix B. The cell origin is o. A Cartesian point is represented by fractional coordinates

\[
f = B^{-1}(x-o).
\]

Only components selected by the periodic-axis mask are wrapped into the half-open interval [0,1). If q is the integer floor vector for those axes, the canonical point is

\[
x_c = o + B(f-q), \qquad x = x_c + Bq.
\]

The returned `LatticeOffset<D>` records q. Non-periodic lattice coefficients remain unchanged and cannot receive a nonzero image offset.

## Closest image is not component rounding

For a displacement d, find integer n on periodic axes minimizing

\[
\|d + Bn\|_2.
\]

The implementation first creates a Babai-rounded candidate n₀ and its distance R. This is only an incumbent upper bound, not the answer by assumption.

For any candidate y = d + Bn that can improve or tie the incumbent, ||y|| ≤ R. With f = B⁻¹d,

\[
|f_i+n_i| = |e_i^T B^{-1} y|
\leq \|\operatorname{row}_i(B^{-1})\|_2 R.
\]

This yields a finite interval for every periodic integer coefficient. The implementation rounds interval endpoints outward, enumerates their Cartesian product, and compares the Cartesian squared norms. Equal computed distances use lexicographic integer-offset tie-breaking. Non-periodic coefficients remain zero.

The query accepts an explicit candidate budget. If the conservative interval product exceeds it, the operation returns a typed `CandidateBudgetExceeded` error; it never silently returns the Babai approximation or a partially searched answer.

This is a bounded floating-point implementation of a finite closest-vector search. It does not claim exact real arithmetic. Extremely ill-conditioned cells, unrepresentable fractional coordinates, and numeric overflow must fail closed or exceed the configured candidate budget.

## Independent conformance ladder

The initial unit corpus covers:

1. A deliberately skew 2D cell where component-wise fractional rounding is not the nearest Cartesian image.
2. 500 deterministic closest-image queries compared with an independently written wider integer-image enumeration.
3. Fractional wrapping, explicit lattice offsets, Cartesian reconstruction and idempotence.
4. Orthogonal-cell agreement with the existing `PeriodicBox` away from half-cell ties.
5. Rotation/basis covariance of the nearest image and integer offset.
6. Partial periodic masks and rejection of offsets on non-periodic lattice axes.
7. Candidate-budget exhaustion and deterministic equal-distance tie handling.
8. Singular and non-finite basis rejection.

These are authored assertions, not passing test results. They require exact-head execution.

## Next performance and integration work

1. Benchmark the exact bounded solver against brute-force image enumeration on the same deterministic 2D/3D skew-cell corpus.
2. Report candidate counts, tail latency, allocation/memory, cell condition, periodic-axis count and failure-budget rate.
3. Add lattice-aware conservative AABB image enumeration. Reuse the brute-force lattice oracle; extra candidates are acceptable and must be counted, missing candidates are not.
4. Add lattice-aware convex queries/CCD only after AABB conformance passes.
5. Keep the existing orthogonal fast path and prove its regression envelope against the old `PeriodicBox` implementation.

## Claim ceiling

This tranche supplies same-dimensional triclinic point wrapping, explicit lattice offsets and a bounded closest-Cartesian-image query. It does not qualify triclinic collision detection, molecular dynamics, arbitrary curved manifolds, periodic contact response, or production physics.
