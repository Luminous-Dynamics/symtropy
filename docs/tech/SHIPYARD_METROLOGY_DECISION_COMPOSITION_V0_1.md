# Point-in-time metrology decision composition v0.1

Tracking: https://github.com/Luminous-Dynamics/symtropy/issues/4749

## Purpose and ownership boundary

This crate composes—not reimplements—three upstream functions:
- scan calibration/registration/coverage/uncertainty qualification (#4736);
- exact signed/added/removed profile differencing and area uncertainty (#4716);
- offline next-pass evidence snapshot and Pareto recommendation (#4649).

It creates a deterministic point-in-time composition receipt. It does not implement calibration, ICP, registration observability, profile integration, weld physics, NDT or a planner. Once upstream crates merge, replace the v0.1 synthetic structs with thin adapters/path dependencies and invoke the actual owner APIs. Do not fork their algorithms.

## Paradigm shift: evidence must be true as known at the decision time

A physical event timestamp alone is not enough. Each receipt carries both measurement/effective time and first-received/known-at time.

The decision cutoff is evaluated using both. A scan first received after cutoff cannot enter a historical recommendation. A revocation or supersession first received after cutoff cannot rewrite the earlier snapshot, even if its claimed effective time is earlier. A revocation known by cutoff and effective by cutoff blocks the decision. Known-but-not-yet-effective lifecycle events remain recorded in the composition receipt.

This gives us event-time and knowledge-time semantics—not “latest database state” semantics.

## Required composition chain

Calibration -> reference and observed scan -> registration -> scan qualification -> geometry comparison -> evidence snapshot -> pass recommendation.

The implementation requires exact workpiece, joint revision, layer and predecessor pass; two distinct source scans with exact SHA-256 digests; exact calibration and registration receipt digests; a qualification receipt bound to the observed scan and calibration/registration receipts; a geometry output bound to reference/observed scan IDs and digests plus the same registration receipt; exact coordinate frame, millimetre length unit and x-grid digest; coverage, unsupported-gap, area-uncertainty and scan-length-uncertainty checks; evidence clock, validity window, measurement time and first-received time; and a point-in-time evidence snapshot, candidate-set digest and planner-build digest.

NDT, repair and learning artifacts are rejected if listed as MediumNextPass features. They belong to the slow quality/requalification loop, not the medium next-pass decision.

## Uncertainty dimensionality

The scan qualification receipt's expanded uncertainty is a length-domain quantity; the profile comparison's uncertainty is an integrated area-domain quantity. The composition checks each against its own threshold. It never adds length and area uncertainty or converts one to the other implicitly.

The geometry receipt preserves signed net area, positive added area and negative removed area as distinct values. The implementation checks that signed net area equals added minus removed, with overflow-safe integer arithmetic.

## V0 claim boundary and hash handling

V0.1 accepts synthetic evidence only. All digests are 64-character SHA-256 values supplied by their evidence producers. This crate verifies format and exact cross-link equality; it does not implement a hash primitive or prove that an upstream producer hashed the correct bytes. The accepted evidence list is sorted so input event ordering cannot change the composition output. The evidence snapshot digest must be generated by the host from a canonical serialized snapshot and retained as source evidence.

A PASS is not optical metrology calibration, physical geometry accuracy, WPS/PQR/WPQT qualification, NDT acceptance, weld integrity or production authority. No live execution, WPS change, automatic pass selection or accepted-as-built write is permitted.
