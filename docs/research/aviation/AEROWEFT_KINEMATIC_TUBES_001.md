# AeroWeft — Kinematic Reachability and 4D Occupancy Tubes

**Status:** design contract / research RFC v0.1  
**Tracking issue:** [AEROWEFT-KINEMATICS-001 #5163](https://github.com/Luminous-Dynamics/symtropy/issues/5163)  
**Parent work:** [AIRSPACE-OPS-001 #2279](https://github.com/Luminous-Dynamics/symtropy/issues/2279), [AIRSPACE-OPS-002 #2297](https://github.com/Luminous-Dynamics/symtropy/issues/2297), [trajectory audit PR #2285](https://github.com/Luminous-Dynamics/symtropy/pull/2285)

**Claim ceiling:** synthetic/offline model research; no operational flight, ATC/UTM, clearance, dispatch, separation-assurance or certification authority.

## 1. Why the next layer is needed

The current trajectory-audit kernel reasons over supplied, piecewise-linear centreline paths with constant horizontal and vertical uncertainty bounds. That is a useful mathematical base, but a supplied polyline does not establish that a particular vehicle can execute it.

The broader Mycelix airspace simulator also explicitly gates its current model applicability to a synthetic constant-velocity toy profile. These are good scope boundaries, not defects to paper over.

AeroWeft should add a separate, versioned model layer between a declared aircraft state and the geometric conflict auditor:

`aircraft profile + initial-state set + control bounds + disturbance bounds
  -> reachable occupancy tube
  -> conservative conflict screening
  -> evidence-qualified human/authority review`

The key shift is from asking only:

> Do these two nominal paths intersect?

to asking:

> Under the declared aircraft model, what space-time occupancy cannot be ruled out, and what evidence supports that statement?

A reachable tube is an outer approximation of possible occupancy. It is not a probability distribution, an intended trajectory, a control solution, a flight clearance, or proof of safety.

## 2. Non-negotiable semantic distinctions

Keep the following objects separate:

1. **Observed state set** — the possible current states after accounting for measurement, timestamp and coordinate uncertainty.
2. **Model parameter set** — the allowed aircraft-performance and configuration parameter ranges for one declared profile.
3. **Control set** — the bounded actions the model permits over the declared horizon.
4. **Disturbance set** — wind and other explicitly represented external effects.
5. **Reachable set** — the possible states generated by the model from those sets.
6. **Numerical enclosure error** — the additional error introduced by the numerical method and representation.
7. **Conflict criteria** — caller-supplied scenario/jurisdiction values with their own validity and provenance.
8. **Operational decision** — an action by a separately authorized person or aviation system.

Do not compress these into one confidence score. Do not treat source reputation, consensus, a valid digest or a successful simulation as a physical error bound.

## 3. First physical model profile: Symthaea-owned fixed-wing dynamics

The aircraft equations, parameters, performance-envelope semantics and applicability limits must come from the existing Symthaea owner [TRANSPORT-FIXED-WING-001 #6249](https://github.com/Luminous-Dynamics/symthaea/issues/6249), composed with candidate-specific mass-coupled mission models (#7729) and adaptive engineering evidence orchestration (#10902). AeroWeft must not create a second aircraft-physics owner.

V0.1 uses one narrowly scoped, synthetic fixed-wing coordinated-turn profile in a local tangent frame. Symthaea owns the declared vector field, profile revision, aircraft-regime limits, parameter/control/disturbance semantics and evidence. Symtropy owns the independent set-enclosure algorithm, numerical soundness obligations, trajectory-tube output and replay. This profile must not be generalized to rotorcraft, multirotors, eVTOL transition, helicopters, high-lift/stall regimes or real aircraft without separate model owners and qualification.

For a declared local East-North-Up frame, a candidate reduced-order model is:

[
\dot x = v_a\cos\psi + w_x,qquad
\dot y = v_a\sin\psi + w_y
]

[
\dot z = v_z + w_z,qquad
\dot\psi = \frac{g\tan\phi}{v_a},qquad
\dot v_a = a_t
]

where:
- (v_a) is airspeed and must remain inside an explicit, positive model domain;
- (psi) is heading in the declared horizontal frame;
- (phi) is bank angle bounded by the profile;
- (v_z) is a declared vertical-speed control interval;
- (a_t) is a declared along-track acceleration interval;
- (w_x,w_y,w_z) are wind/disturbance components;
- (g) is the declared gravity constant and units are SI.

The coordinated-turn relation is only an illustrative candidate model for interface discussion; it is not a model validated or owned by Symtropy. The Symthaea fixed-wing owner must specify the actual reduced-order equations and identify omissions such as roll transients, sideslip, propulsion dynamics, structural/load limits, stall behaviour, wake, icing and detailed aerodynamic performance. The set-enclosure implementation must return unsupported/not-assessable outside the exact profile supplied by that owner.

### 3.1 Required profile inputs

- profile ID, revision, aircraft class and operating-regime label;
- source/evidence state (synthetic, candidate, reviewed, unsupported);
- positive airspeed interval and permitted acceleration interval;
- bank-angle interval and declared turn-model assumption;
- climb/descent-rate interval;
- initial position, heading and speed set;
- bounded wind vector and its time/space validity scope;
- time origin, horizon and time-step policy;
- horizontal CRS/local-frame ID, axis order, vertical datum and units;
- model applicability limits and explicit exclusions;
- input and profile digests, toolchain/model revision and deterministic seed where applicable.

All numerical values in the initial fixtures must be clearly fictional and labelled synthetic. No real-aircraft limits should be copied into a fixture and then presented as validated model parameters.

## 4. Reachability method: compare before selecting

The first task is to compare viable outer-enclosure methods on the same frozen, low-dimensional model:

- interval arithmetic with validated ODE integration;
- Taylor models / validated Taylor integration;
- zonotopes or constrained zonotopes;
- support-function or template-polytope methods;
- conservative adaptive gridding as a baseline, with explicit coverage gaps.

Do not accept an ordinary floating-point point integrator plus an arbitrary epsilon as a reachability method. The chosen method must define how truncation, round-off, parameter and disturbance effects are enclosed. When the bound cannot be established within the declared numeric domain or computation budget, it must return an explicit unresolved result.

A good first prototype may use an axis-aligned outer box because it is easy to inspect and independently check. Its conservatism must be measured. Correlation loss and box inflation are first-class metrics, not invisible implementation details.

## 5. Tube contract

A tube consists of ordered time slices. Every slice must bind:

- `[t_start, t_end)` and the time scale/clock assumptions;
- model profile ID/revision and applicability result;
- coordinate frame, vertical datum, axes, units and transformation lineage;
- outer-set representation and its numeric enclosure bound;
- initial-state, parameter, control and disturbance dependencies;
- separately reported initial-position, velocity-estimation, model-parameter, control, environmental-disturbance and numerical contributions;
- input, scenario, source and toolchain digests;
- deterministic ordering and stable slice identity;
- terminal disposition: `Enclosed`, `UnsupportedModel`, `InvalidInput`, `BudgetExhausted` or `NotAssessable`.

A tube should preserve enough lineage to explain which input expanded each bound. A single scalar 'uncertainty radius' is not an acceptable substitute for this information.

### 5.1 Reachable occupancy is not trajectory feasibility

This distinction is essential:

- If a candidate state is outside the validated reachable set at a time, the candidate is infeasible under that model.
- If a candidate state is inside a conservative reachable set at every time, that alone does **not** prove one continuous, dynamically consistent control sequence realizes the entire path. Each point may be reachable under a different control history.

A future trajectory-feasibility checker must preserve temporal/control dependencies and return a witness or an independently verified feasibility certificate. V0.1 must label tube-membership checks as necessary screening only.

### 5.2 Conflict semantics

For two aircraft, intersection of conservative occupancy tubes means **possible conflict under the declared model**, not proof that a collision will occur. Disjoint outer tubes can exclude a conflict only within the declared model, numeric domain, validity horizon and source coverage. Missing dynamics, unsupported modes, stale disturbances, inadequate coverage or exhausted computation must never be converted to 'no conflict'.

Pairwise geometric audit remains a separate narrow-phase step. Broadphase candidate generation remains the separate responsibility of #2297.

## 7. Benchmark ladder

Targets below are proposed research acceptance criteria, not current results.

### A. Outer-enclosure soundness
- 100% containment against an independently implemented analytic/interval oracle on a frozen bounded corpus.
- Zero under-approximations. Any missed reachable state is a hard failure.
- Report tube inflation/volume ratio and enclosure width, not just pass rate.
- Sampled high-fidelity trajectories are useful falsification data but are not by themselves proof of outer-set containment.

### B. Conflict-screen quality
- Zero false-safe outcomes against an independent reachable-set conflict oracle on the bounded corpus.
- Report false-positive rate, false-negative rate, tube inflation and unresolved rate separately.
- Distinguish 'possible conflict', 'excluded within model', 'not assessable' and 'model unsupported'.

### C. Metamorphic and monotonicity laws
- Widening the initial-state, wind, parameter or control set must not shrink the output reachable set under the declared ordering.
- Equivalent time-origin shifts and valid frame translations must preserve the corresponding result.
- Refinement must preserve containment; reduced conservatism is measured, never assumed.
- Permuting input records must not change canonical results.
- Tightening computation budgets must produce an explicit unresolved/budget-exhausted outcome, not a smaller tube.

### D. Model applicability
- 100% rejection of unsupported classes/regimes and invalid airspeed domains.
- 100% rejection of unqualified frame/datum/unit/time inputs.
- 100% fail-closed behavior for missing wind bounds, expired model profiles, non-finite inputs, arithmetic overflow and unsupported horizons.
- Do not report performance on unsupported traffic archetypes as if those cases were evaluated.

### E. Performance
At each declared horizon, aircraft count and tube subdivision count report:
- p50/p95/p99 runtime;
- peak and allocated memory;
- number of interval subdivisions/branches;
- tube inflation versus the independent reference;
- conflict candidate count and narrow-phase calls;
- unresolved/budget-exhausted cases;
- full reproducibility manifest and toolchain.

Pin hardware and compare the same frozen workloads before making latency or scalability claims.

## 8. Fair industry comparison

Do not claim to replace established specialist systems. Compose with them and compare only matched functions.

| Reference | Relevant capability | AeroWeft comparison |
|---|---|---|
| EUROCONTROL Trajectory Prediction Specification, Ed. 2.0 | Requirements/guidance for planned and tactical trajectory modelling; separates intent from trajectory/performance prediction | Compare state, intent, environment and performance-model lineage; measure prediction error against a matched reference |
| EUROCONTROL medium-term conflict detection | Traffic prediction and detection of relevant encounters/restricted-airspace penetration | Compare event semantics, coverage, false alarms, lead time and uncertainty handling, not only geometric runtime |
| NASA Formal Methods / air-traffic research | Formal methods and state-based conflict detection/resolution research | Independently verify invariants and model assumptions; do not equate test count with assurance |

| OpenVSP / OpenMDAO / Dymos | Specialist geometry, multidisciplinary design and trajectory optimization | Consume and preserve their configuration and analysis artifacts instead of rebuilding mature tools |
| Current Mycelix/Symtropy synthetic baselines | Constant-velocity paths and evidence-bound coordination | Demonstrate the incremental value and cost of model-specific set-valued dynamics |

EUROCONTROL reference: https://www.eurocontrol.int/publication/eurocontrol-specification-trajectory-prediction  
NASA Formal Methods: https://shemesh.larc.nasa.gov/  
FAA UTM: https://www.faa.gov/uas/advanced_operations/traffic_management  
EASA U-space: https://www.easa.europa.eu/en/domains/air-traffic-management/u-space

The decisive comparisons are:
1. point prediction vs conservative reachable occupancy;
2. single nominal aircraft model vs profile-qualified model families;
3. arbitrary fixed margins vs separately attributable state/model/disturbance/numerical bounds;
4. one aggregate conflict score vs hard-gated false-safe/false-alarm/abstention metrics;
5. a local algorithm result vs a fully replayable cross-project evidence chain.

No claim of SOTA superiority is justified until an independent evaluator freezes data, scenario coverage, baselines, implementation revisions and hardware.

## 11. Explicit exclusions

No live traffic, surveillance or flight-plan ingestion; no operational weather feed; no aircraft-performance certification; no approved separation minima; no tactical instructions; no automated manoeuvre; no dispatch/clearance; no ATC/UTM connection; no onboard control; no airworthiness or regulatory conclusion; no physical trials.

**AeroWeft's first success condition is not finding a route. It is being honest about the set of futures the declared model can and cannot rule out.**


## 12. First executable foundation — 2026-11-14

An isolated, dependency-free Rust research crate now exists at
`tools/aeroweft-reachability` on the AeroWeft kinematic branch. It propagates
finite position intervals through contiguous, caller-supplied, per-axis
bounded-velocity intervals and emits an axis-aligned occupancy box for each
time slice. The crate keeps additive nominal-velocity, velocity-estimation,
model-parameter, control and environmental-disturbance contributions
separately represented in the request. It expands
binary64 addition and multiplication results outward by one representable
step, rejects non-finite/overflow cases, and carries profile, frame and
vertical-datum identifiers.

The first corpus contains seventeen unit-test definitions and two separately
compiled integer-reference integration tests: positive one-axis and signed
three-axis cases using integer millimetres and milliseconds. The dedicated workflow runs format, Clippy and locked
tests for this standalone workspace.

**This is only an interval integration foundation.** It does not derive
velocity bounds from bank angle, airspeed, aircraft performance, weather or
any real aircraft model. It does not implement the aircraft dynamics profile owned by Symthaea #6249. The caller must establish that every supplied
velocity interval contains all instantaneous velocities over the entire
slice. Axis-aligned interval propagation discards correlation and may become
very conservative. A one-ULP arithmetic enclosure is not a proof of the
physical model or all model/transform uncertainty.

No exact-head Rust execution result has been established by this authoring
session. The test definitions and workflow are present; they are not claimed
as passed evidence.


## 13. Benchmark data admission and matched industry comparators\n\nThe standalone [AeroWeft Benchmark Suite V1](AEROWEFT_BENCHMARK_SUITE_V1.md) defines the full seven-track evaluation, baselines, rights-aware data admission and confirmatory protocol.

AeroWeft must maintain two separate evaluation tracks:

### 13.1 Deterministic bounded-set track

For a frozen, declared model domain, evaluate conservative outer-set containment and conflict-screen false negatives. The acceptance target is zero under-approximation against the independent, bounded reference oracle. This is a statement about the declared mathematical domain, not a claim that the model covers all real aircraft behaviour.

### 13.2 Probabilistic prediction/conformance track

Where a qualified probabilistic error model exists, separately evaluate empirical coverage at 90%, 95% and 99%, calibration, sharpness, alert lead time and shift degradation. EASA U-space guidance discusses authorised 4D volumes that account for UAS performance, operator proficiency and weather, with 95% containment as an expected level in the cited guidance. Its conformance-monitoring guidance also specifies alerts within five seconds for 99% of detected non-conformance events. These are jurisdiction- and service-scoped comparison points, not universal AeroWeft requirements, not deterministic reachable-set guarantees, and not interchangeable with worst-case outer-enclosure soundness.

Never combine deterministic containment and probabilistic coverage into one score. A system may be highly calibrated while still having tail failures; a worst-case box may be sound but too inflated to be operationally useful. Report both the assurance claim and its efficiency cost.

### 13.3 Data-source admission

Start with synthetic golden cases and independently generated analytic/interval oracles. For real or archived traffic:
- OpenSky Network provides scientific and historical air-traffic datasets, but full historical access is described as available to university-affiliated researchers, government organisations and aviation authorities; private/commercial use requires a licence. The public API and each scientific dataset have separate access/terms. Do not use it as unrestricted commercial training or redistribution material.
- EUROCONTROL's Demand Data Repository is a restricted/licensed stakeholder service; access conditions apply to ANSPs and airline operators, and some API endpoints have narrower eligibility. Do not assume it is a public benchmark feed.
- FAA UTM Field Test publications provide useful real-world validation context and report focus areas such as planning/coordination, priority of operational intent, data correlation, identity and access management. A published report is not equivalent to access to the underlying raw operational dataset.
- Any South African airspace, aerodrome, NOTAM, weather or aircraft data must be admitted only after the exact publisher, edition, rights, effective period, coverage, transformations, vertical datum and intended research/commercial use are reviewed.

Every admitted dataset needs immutable source/version/digest records, rights status, time and geography coverage, aircraft/equipage coverage, missingness, calibration, truth/adjudication process, clock quality and leakage-safe group identifiers. Split by flight, aircraft/session, receiver/site, day, region and environmental regime as applicable. A random row-level split is not confirmatory evidence when correlated samples from the same flight or sensor can appear on both sides.

### 13.4 Matched baseline matrix

| Baseline | Matched question |
|---|---|
| Current Symtropy piecewise-linear audit (#2285) | What is gained by model-derived occupancy versus supplied centreline paths? |
| Current Mycelix constant-velocity toy model (PR #5024) | What does explicit interval lineage add beyond synthetic constant-velocity conflict/restriction coordination? |
| Point-estimate performance model | How much does set-valued reachability change false-negative rate, false-positive rate and compute cost? |
| Interval/Taylor/zonotope methods | Which outer-enclosure method gives the best soundness/conservatism/runtime trade-off on the same equations and inputs? |
| Fixed 4D volume reservations | How much capacity is recovered by model-qualified time-dependent occupancy, without relaxing safety constraints? |
| FIFO, shortest-feasible and rolling-horizon capacity-aware planners | How do throughput, delay, stability, fairness and recovery compare on exactly the same network/scenarios? |
| EUROCONTROL trajectory-prediction requirements and NASA formal-methods work | Do our model/intent separation, independent verification, scope, failure semantics and evidence traceability meet the relevant research/practice expectations? These are reference specifications and research programmes, not drop-in numerical baselines. |

For every performance comparison freeze the inputs, horizon, aircraft models, uncertainty assumptions, source vintage, candidate search space, objective, hard constraints, hardware, toolchain and implementation revision. Report p50/p95/p99 end-to-end latency and memory, but also prediction error, coverage, tube inflation, false alarms, missed conflicts, abstention, throughput and community outcomes. Candidate-generation latency alone must never be presented as full conflict-management performance.
