# AeroWeft Model / Intent / Authority Boundary V1

**Status:** cross-project interface contract / design v0.1  
**Consumers:** Symthaea fixed-wing model owner #6249; Symtropy reachability #5163 and airspace #2279; Sol-Atlas #189; Mycelix #5023  
**Claim ceiling:** evidence and interface contract only; no operational flight authorization or safety assurance.

## 1. Purpose

Prevent the cross-project stack from silently collapsing mission intent, aircraft performance, predicted trajectory, reachable occupancy, resource reservation and legal authorization into one "route" object.

EUROCONTROL's trajectory-prediction specification explicitly distinguishes aircraft intent from the trajectory engine that computes motion using an aircraft performance model. AeroWeft must preserve that distinction across repositories and versioned artifacts.

## 2. Separate semantic objects

| Object | Meaning | Owner / producer | Must not be inferred |
|---|---|---|---|
| Mission request | Origin/destination, service goal, payload class, deadline, priority policy | Mission/transport layer | A flight plan or clearance |
| Aircraft intent | Desired operation/profile, route goals or target windows, time constraints | Authorized operator / separately scoped planning service | Actual achievable motion |
| Aircraft configuration | Exact vehicle configuration, mass properties, software and equipment state | AeroCommons / aircraft engineering | Airworthiness |
| Physical model profile | Equations/maps, parameter domain, aircraft-regime scope, assumptions and validation evidence | Symthaea #6249 and discipline owners | Certification or truth outside applicability |
| Environment profile | Wind/weather/disturbance assumptions, spatial and time scope, uncertainty | Source-qualified providers / Sol-Atlas context | Perfect knowledge of the environment |
| Trajectory prediction | A nominal or probabilistic predicted motion from intent + model + configuration + environment | Model/trajectory engine | A reachable set or authorization |
| Deterministic reachable enclosure | Outer set containing all states admitted by the bounded model and numeric contract | Symtropy #5163 | A feasible control witness or all-world safety |
| Probabilistic prediction envelope | Calibrated likely-motion volume under a declared stochastic model/data regime | Model owner + independent calibration | A deterministic guarantee |
| Resource reservation | Versioned request/claim on time-dependent spatial or ground resources | Coordination/allocator, Mycelix #5023 for provenance | Legal authorization |
| Authority decision reference | Pointer to a decision made by the competent aviation authority / approved service | Competent authority or authorized service | A decision generated by a receipt, ledger or optimizer |
| Operational observation | What a qualified source actually observed, with time/quality/provenance | Authorized sensor/source adapter | Intent or identity without corroboration |

## 3. Required lineage

Every trajectory or reachable-set result must bind:
- mission and flight-intent IDs/revisions (or explicitly state not applicable);
- aircraft configuration ID/revision and applicable equipment/software state;
- physical model profile ID/revision, exact source/evidence references and applicability domain;
- mass, centre-of-gravity, inertia and payload profile where relevant;
- environment/disturbance profile and source vintage;
- initial state set, control set, parameter set, time basis and horizon;
- horizontal coordinate frame, axis order, vertical datum and unit definitions;
- transformations and their uncertainty/error lineage;
- enclosure algorithm, numeric domain, code/toolchain revision and error bound;
- scenario/constraint snapshot and validity period;
- unsupported, stale, conflicting, rejected and unresolved inputs;
- exact output digest and independent verifier identity/receipt.

A digest verifies byte identity only when the expected digest itself is trusted; it does not authenticate a source or prove physical validity.

## 4. State separation and typed outcomes

Do not reuse one boolean `valid` field across layers. Use a distinct status for each claim:

### Model profile
- `Synthetic`
- `Candidate`
- `ReviewedForDeclaredDomain`
- `Unsupported`
- `RevokedOrSuperseded`

Only the model owner and review process can establish a profile's evidence state. A caller-supplied status label is not authentication.

### Enclosure result
- `EnclosedWithinDeclaredDomain`
- `UnsupportedModelOrRegime`
- `InvalidInputOrReference`
- `BudgetExhausted`
- `NotAssessable`

A result may claim outer enclosure only when the model applicability, input coverage and numerical obligations are satisfied. A probabilistic estimate must be a different result type.

### Resource allocation
- `Candidate`
- `ConflictFreeUnderDeclaredModel`
- `CapacityBlocked`
- `UnresolvedDependency`
- `ExpiredOrSuperseded`

A resource allocation is not an authorization.

### Authority decision
- `NotProvided`
- `Referenced`
- `ExpiredOrWithdrawn`
- `Unknown`

Only the competent external authority/service can provide the relevant decision. No other layer may promote a reservation to an authorization.

## 5. Cross-project division of responsibility

### Symthaea
Owns physical model profiles and applicability:
- fixed-wing aerodynamics/flight dynamics #6249;
- candidate-specific mass-coupled mission model #7729;
- adaptive evidence-gathering #10902;
- model selection, parameter uncertainty, discrepancy and advisory analysis.

It does not certify its own model, approve airworthiness or issue flight clearance.

### Symtropy
Owns independent set-enclosure and operational-research mathematics:
- reachable-set algorithm and proof/assumption contract;
- numerical conservatism, validated integration and independent oracles;
- tube/trajectory composition and conflict-screen input adapter;
- resource/capacity simulation and deterministic replay.

It does not create a second aircraft physics model or command aircraft.

### Sol-Atlas
Owns read-only spatial context:
- source-qualified airfields, airspace, obstacles, terrain, weather coverage, energy and ground-transfer context;
- CRS/datum/transformation, source freshness, data rights and geographic coverage.

It does not infer that missing geometry is unrestricted or that a mapped site is operational.

### Mycelix
Owns identity, access and provenance:
- provider/actor identities and scoped credentials;
- versioned intent/reservation/evidence receipts;
- revocation, supersession, dispute and cross-provider audit.

Consensus, reputation or a ledger entry is never a physical truth or real-time separation mechanism.

### External aviation authorities and certified systems
Retain applicable regulatory, airworthiness, operating-approval, separation, onboard detect-and-avoid and flight-control responsibilities.

## 6. Required independent gates

1. **Intent gate:** identity, scope, time, units and requested operating regime are explicit.
2. **Configuration gate:** exact aircraft configuration and mass/property inputs resolve.
3. **Model gate:** profile revision and applicability domain resolve; unsupported regimes abstain.
4. **Environment gate:** disturbance and source coverage are adequate for the claim.
5. **Prediction gate:** intent and model remain distinct; nominal path and probabilistic output are not treated as hard bounds.
6. **Reachability gate:** independent enclosure method checks its mathematical obligations.
7. **Conflict/resource gate:** reachable occupancy is compared with the same frozen airspace/resource snapshot; unresolved constraints remain unresolved.
8. **Authority gate:** a separately issued authority decision is referenced where required; the software does not infer or synthesize it.
9. **Replay gate:** exact inputs, model, code, toolchain, rejected records and verifier output are reproducible.

No later gate can repair a missing earlier input by guessing.

## 7. Adapter contract

The first adapter should be deliberately narrow. Symthaea supplies a versioned, source/evidence-bound profile and a bounded step/flow contract. Symtropy consumes only the declared outputs and independently computes/validates an enclosure. The adapter must not pass arbitrary executable closures or invoke Symthaea's internal solver as the verifier.

A v0.1 adapter fixture should include:
- profile ID/revision and applicability status;
- declared synthetic model regime and frame/datum/units;
- initial-position set;
- separately bounded nominal velocity, velocity-estimation, model-parameter, control and environment contributions for each time slice;
- time validity and coverage;
- exact fixture-byte digest and explicit unsigned status;
- expected outer enclosure from an independently implemented integer/rational oracle;
- negative mutations for source/profile identity, applicability, missing dimensions, unit/datum mismatch, horizon extension, invalid time and uncertainty narrowing.

The current `tools/aeroweft-reachability` crate is only the propagation primitive. This document is the target interface boundary, not evidence that a Symthaea-to-Symtropy adapter exists yet.
